# Native desktop continuation — 7 September 2026

## Current status

The C++26/Qt client now covers the ordinary local Git workflow, multi-account
identity selection, list history and an optional all-branch graph. Source work
is on `codex/native-completion`. The Electron implementation remains frozen.
This is **not a claim of complete upstream GitHub Desktop feature parity or a
verified macOS/Windows release**.

## User-facing additions

- Settings in the application menus: refresh on focus, diff font size, local
  Git identity, account management and the optional all-branch history graph.
  List history remains the default. Filtering hides graph edges rather than
  connecting unrelated visible commits.
- New local repository, origin URL setup and a GitHub publication dialog with
  private visibility selected by default. Publication captures the displayed
  account, verifies the authenticated GitHub owner, creates the remote and
  pushes the branch. Partial failures include recovery instructions.
- Local branch creation, rename, deletion of merged branches, remote checkout,
  local/remote branch merge and rebase of unpublished commits.
- Conflict dialog with whole-file ours/theirs selection, marking externally
  edited files resolved, continue, abort and skip where supported. Git side
  semantics during rebase are explained. Errors remain visible in the dialog.
- Stash tracked/untracked work, restore both the index and working tree, and
  explicitly delete saved stashes. Applying keeps its recovery copy.
- Discard selected files through a retained full recovery snapshot. Rename and
  staged-deletion paths are restored correctly; unrelated staged/unstaged work
  is preserved. Tracked-file-to-directory replacements are refused before
  stashing because Git cleanup can otherwise delete ignored data.
- Revert and cherry-pick selected commits; undo a latest unpublished commit,
  including an initial commit; restore its message when no existing draft would
  be overwritten. Edit the latest unpublished commit message without including
  unrelated staged changes. Create/delete local tags.
- Before/after raster-image previews in Changes and History, bounded by encoded
  size and decoded dimensions. Missing content is distinguished from unsupported,
  oversized or unreadable content. Symlinks never preview their target contents.

## Engineering behavior

- Repository mutations serialize; account mutations and repository writes cannot
  overlap. Repository activation and creation are rejected while a mutation is
  active, avoiding snapshots from before a write. Cloning permits browsing an
  existing repository, while retaining its account/mutation lock. A closed view
  does not swallow a mutation's failure.
- Commit identity is the bound/active GitHub account, otherwise the explicit
  Settings identity with missing fields falling back to effective repository
  Git configuration. The exact name/email is displayed and used for all
  commit-producing operations. Tokens never cross into widgets.
- Graph pages preserve a snapshot of branch tips. Hashes travel through stdin,
  avoiding Windows command-line limits, with one batch validation per page.
  Ordinary list mode does not calculate graph geometry.
- Stash does not inherit Git's global literal-pathspec mode, which breaks its
  internal untracked cleanup. Selected paths remain literal in other commands.
- GitHub API calls restrict the host, disallow redirects, and bound total time
  and response size. Publication checks the owner and preserves a selected
  account binding before performing a remote write. Origin editing refuses
  ambiguous explicit push URLs and embedded credentials.
- Native application and tests link the same core library; sources are no longer
  compiled twice for the executable and library.

## Review and validation

Five independent reviewers examined Git/data preservation, UI behavior, async
identity handling, graph/paging and final integration. Their concrete findings
were fixed, including ignored-file deletion during stash, staged rename discard,
index-only stash content, duplicate stash hashes, stale image labels, partial
publication recovery and Windows command-line limits.

Validation environment remains Linux x86-64, Clang 19/C++26, CMake 3.31 and Qt
6.8.2 from an isolated toolchain. The production pin remains Qt 6.11.1.
The final integration build passed all 20 CTest suites (16.39 seconds),
including application smoke, temporary-repository Git workflows, UI tests and
the packaging verifier. `git diff --check` also passed. Image, graph, settings
and conflict screenshots were inspected locally.

Tests operate on temporary repositories and cover actual Git writes. UI tests
exercise the controller, history mode switching and a conflicted merge with a
visible dialog error. Screenshots can be regenerated by setting
`RELAY_SCREENSHOT_DIR` before CTest. No real account login, publication or remote
push was executed during development.

`.github/workflows/native.yml` prepares build/CTest jobs for macOS arm64 and
Windows x64 with pinned Qt and upstream LLVM `clang++`. Windows uses the MSVC
target and dynamic runtime to match Qt. CMake's AppleClang/MSVC/clang-cl mappings
do not provide the required C++26 mode. The workflow has not been uploaded or
run. Runner choices and
Qt setup follow [GitHub's runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)
and the [Qt setup action](https://github.com/jurplel/install-qt-action).
Publication uses the documented [repository creation endpoint](https://docs.github.com/en/rest/repos/repos#create-a-repository-for-the-authenticated-user).

## Still required before release or full parity claims

- Run pinned native builds and GUI checks on macOS arm64 and Windows x64.
- Prepare reproducible platform Git/gh payloads, build and install the real
  installers, check platform menus/window lifecycle/accessibility/scaling, and
  measure footprint and startup time.
- Verify multi-account login, private clone/fetch/push, publication and credential
  store reuse in both installed applications using explicitly authorized test
  repositories. Offline tests do not prove these remote workflows.
- Signing/notarization and release publication are not configured or performed.
- Advanced upstream workflows such as line/hunk selection, interactive commit
  rewriting, integrated pull-request review, editor configuration and complete
  settings/theme parity are not implemented. Tags are local; force-pushing and
  rewriting known published commits are intentionally unavailable.
